# MusicFree 插件 —— 阿里云盘

把阿里云盘当作你的私人音乐库，在 [MusicFree](https://github.com/maotoumao/MusicFree) 里搜索、浏览和播放自己云盘上的音乐。

基于**阿里云盘官方开放平台 API**（`openapi.alipan.com`）实现，只需要一个 `refresh_token`，**无需抓包、无需设备签名**。

## 功能

| 入口      | 说明                                           |
| ------- | -------------------------------------------- |
| 搜索 → 单曲 | 全盘搜索音频文件（支持翻页）                               |
| 搜索 → 歌单 | 把「音乐目录」下的**文件夹**当作歌单列出，点进去就是该文件夹里的歌          |
| 搜索 → 专辑 | 与「歌单」内容完全一致（同一批文件夹的另一种呈现）                    |
| 推荐 → 歌单 | 多一个「全部文件夹」标签，**不用输关键词**就能浏览所有文件夹             |
| 排行榜     | 两组：「**全部歌曲（含子目录）**」递归汇总所有音频；「**目录**」按文件夹逐层浏览 |
| 播放      | 取 4 小时有效的直链播放                                |
| 歌词      | 自动查找歌曲**同目录同名的 `.lrc`** 文件（找不到会提示，属正常）       |

其他细节：

- **自动读取云盘文件的内嵌标签**（标题 / 歌手 / 专辑 / 封面 / 时长），读不到时再从 `歌手 - 歌名.flac` 这类文件名解析
- **自动过滤**图片、视频、文档等非音频文件
- 支持**多云盘**：默认云盘 / 资源库 / 备份盘，音乐放在资源库里也能正常用（默认覆盖全部）
- **令牌自动接力**：刷新得到的新令牌会自动存下来，重启软件也不会因为旧令牌作废而掉线（桌面版）
- 接口限流自动退避重试；大曲库的递归遍历分片续跑，不会卡死

## 安装

### 方式一：网络导入（推荐）

在 MusicFree 中：**侧边栏 → 插件管理 → 从网络安装**，粘贴下面的地址：

```
https://fhvyxyci.github.io/musicfree-plugin-aliyundrive/aliyundrive.js
```

这个地址走 **GitHub Pages**，通常比 `raw.githubusercontent.com` 更容易在国内直连成功——后者常年被 DNS 污染，是大家最常遇到打不开的那个。但要注意：两者其实**跑在同一段 GitHub 线路上**（都是 Fastly 的 `185.199.108.0/24`，只是域名不同），所以**谁都不能保证一定通**。打不开就按顺序换：

| 备用地址                                                                                          | 说明                   |
| --------------------------------------------------------------------------------------------- | -------------------- |
| `https://raw.githubusercontent.com/fhvyxyci/musicfree-plugin-aliyundrive/main/aliyundrive.js` | GitHub 原始地址，部分网络反而更快 |
| `https://ghproxy.net/https://fhvyxyci.github.io/musicfree-plugin-aliyundrive/aliyundrive.js`  | 加一个公益加速前缀            |

（`ghproxy.net` 是第三方公益加速服务，可用性不受本项目控制。都不行就走下面的本地导入。）

这几个地址取到的文件内容完全一样。另外 GitHub Pages 每次推送后要构建一两分钟，刚更新完可能还拿到旧版本；`raw` 与 Pages 的缓存时间也略有差别。

### 方式二：本地导入

从 [GitHub 仓库](https://github.com/fhvyxyci/musicfree-plugin-aliyundrive) 下载 `aliyundrive.js`（页面上点开该文件后另存，或用 Code → Download ZIP 解压），在 **插件管理 → 从本地文件安装** 中选中它。

安装后在插件列表里**启用**它，然后点进插件设置填写变量（见下一节）。

## 配置变量

插件设置里共 6 项，**只有第 1 项是必填的**：

| # | 变量                       | 必填 | 填什么                                                                                           |
| - | ------------------------ | -- | --------------------------------------------------------------------------------------------- |
| 1 | **刷新令牌 (refresh_token)** | ✅  | 见下方[获取刷新令牌](#获取刷新令牌)                                                                          |
| 2 | **音乐目录**                 | 选填 | 留空或填 `root` = 从云盘根目录开始；也可填目录路径（如 `/music`）或目录 ID；多个目录用**英文逗号**分隔                              |
| 3 | **云盘类型**                 | 选填 | `all`（全部云盘，**默认，推荐**）/ `default`（仅默认云盘）/ `resource`（仅资源库）/ `backup`（仅备份盘）                     |
| 4 | 客户端ID (ClientID/AppID)   | 选填 | 自建应用的 AppId。填了之后令牌**直接向官方接口刷新**，不经过任何第三方（⚠️ 对于阿里云盘，个人开发者已无法申请，见[下文](#想完全不经第三方自建应用现在对个人基本走不通)） |
| 5 | 应用密钥 (AppSecret)         | 选填 | 与第 4 项配套，**两项都填**才会走官方直连                                                                      |
| 6 | 令牌刷新服务地址                 | 选填 | 仅在没填第 4、5 项时生效，默认 `https://api.oplist.org/alicloud/renewapi`，不用改                              |

### 最小可用配置

```
刷新令牌   : <粘贴你获取到的 refresh_token>
音乐目录   : /music        ← 换成你自己的音乐文件夹路径
（其余留空）
```

## 获取刷新令牌

1. 浏览器打开 **<https://api.oplist.org>**（大陆访问不畅时可以试国内站 `api.oplist.org.cn`，同一套流程）
2. 驱动下拉选 **「阿里云盘 应用登录」**  
   （⚠️ 不要选「阿里云盘 直接登录」，那个流程的服务端刷新接口有 bug，上游会拒）
3. **勾选**「使用 OpenList 提供的参数」，ClientID 与 AppSecret **都留空**
4. 点「获取 Token」→ **用阿里云盘 App 扫码登录**
5. 复制返回的 **Refresh Token**，粘贴到插件设置的第 1 项

这一步会经过第三方服务器，怎么评估见[关于令牌](#关于令牌)。

## 关于令牌

这一节把令牌的来龙去脉讲清楚，你可以自己核对。

### 两种令牌，两种「过期」

| 令牌              | 有效期        | 过期后              |
| --------------- | ---------- | ---------------- |
| `access_token`  | **约 2 小时** | 插件**自动续期**，你完全无感 |
| `refresh_token` | **90 天**   | 真的失效了，需要重新获取一个   |

### 刷新会「滚动」签发新令牌

阿里云盘官方文档对刷新接口的说明是：*刷新 tokenInfo 会返回新的 tokenInfo，**旧的 tokenInfo 会失效***。

而 MusicFree 的插件变量是**只读**的——插件没法把新令牌写回你的配置。本插件用两层接力兜住这件事：

| 时机       | 做法                                                        |
| -------- | --------------------------------------------------------- |
| **运行期间** | 新令牌存在内存里，同一次运行只刷新一次，之后长期可用                                |
| **重启之后** | 新令牌写入 MusicFree 的**本地插件存储**（`musicfree/storage`），下次启动优先用它 |

落盘时只保存「**原令牌的指纹**（哈希）+ 最新令牌」，**不重复明文保存你填的那份**。指纹的另一个用处是：你在设置里换了令牌，指纹对不上，插件就会自动忽略旧缓存、改用新填的那份。

> **移动端只有内存这一层。** MusicFree 移动端沙箱目前没有注入 `musicfree/storage`（见官方 issue #650；截至 2026-10，公开的移动端源码里 `packages` 白名单中仍然只有 cheerio / crypto-js / axios / dayjs / big-integer / qs / he / cookies / webdav）。
>
> 但这不等于安卓版得天天重填。同一次运行里，`access_token` 约 2 小时自动续期、轮换出来的新 `refresh_token` 一直留在内存里，**开着用多久都没事**。问题只出在重启那一刻：内存清空，只能回头用设置里那份原始令牌，而它早被轮换过了——服务端对旧令牌还留着一小段宽限期，所以隔不久重启通常能自己接上，但**放上几十天再重启，往往就得重新获取一个令牌了**。桌面版有落盘那一层，没有这个问题。

如果哪天提示「刷新令牌失败」，说明那个令牌真的失效了（过期，或已在别处被用掉），**重新获取一个填进去即可**。

### 令牌会经过第三方服务器

上面那个网站（`api.oplist.org`）是开源项目 [OpenListTeam/OpenList-APIPages](https://github.com/OpenListTeam/OpenList-APIPages)，部署在 Cloudflare Worker 上。读过它的源码后，链路是这样的：

**两个环节都经过他们的服务器：**

| 环节                     | 请求由谁发出                                       |
| ---------------------- | -------------------------------------------- |
| 生成令牌（扫码后「授权码 → 令牌」的交换） | **他们的服务器**（`alyToken` 里由后端 `fetch` 阿里云盘接口完成） |
| 之后**每次刷新**             | 同样是**他们的服务器**（`genToken` 读取 URL 参数后代发上游请求）   |

而且刷新时 **refresh_token 是放在 URL 查询串里的**：

```
https://api.oplist.org/alicloud/renewapi?refresh_ui=<你的刷新令牌>
```

URL 参数会进访问日志，比放在请求体或 header 里更容易被留存。而这串东西是 90 天有效的长期凭证，**等同于你云盘的读写权限**。

还有两点要注意：

- 勾选「使用 OpenList 提供的参数」时，用的是**他们的公共应用身份**（源码里的 `c.env.alicloud_uid`），所有用户共用一个 app。
- **不要**在那页填自己的 ClientID / AppSecret——那两个值同样是通过 URL 参数传给他们服务器的，填了不但没换来安全，反而白送密钥。

### 想完全不经第三方？自建应用（现在对个人基本走不通）

> ⚠️ **阿里云盘开放平台已经关闭了个人申请通道。**  
> 自 **2025 年 7 月 1 日**起，官方暂停受理**个人开发者**的注册申请——登录开发者后台会直接提示  
> 「你还不是阿里云盘开发者，无法登录开发者后台」，目前只受理**企业开发者**（需邮件联系官方对接）。
>
> 也就是说，下面这条「自建应用」的路**对个人用户基本已经走不通了**。把它保留在这里，是为了说明原理，  
> 以及给已经持有开发者身份（或背后有企业主体）的人参考。
>
> 这也正是本插件默认走 OpenList 公共刷新服务（第 6 项变量）的原因——**不是图省事，而是现在没有别的选择**。  
> 好在按下面的成本算下来，走 OpenList 这条路既合规、也几乎不占用对方资源。

> 下面这个方法是AI自己写的，我也没办法测试，看个乐就好

如果你有条件走这条路，refresh_token 与签发它的应用绑定，**事后换通道是无效的**，只能从第一步就开始：

1. 在**阿里云盘开放平台**申请一个应用，拿到 AppId 与 AppSecret
2. 用官方接口完成扫码授权：`/oauth/authorize/qrcode` → 扫码 → `/oauth/qrcode/{sid}/status` → `/oauth/access_token`。这四步**可以完全在你本机完成**，不需要任何服务器
3. 把得到的 refresh_token 填进第 1 项，AppId / AppSecret 填进第 4、5 项——插件的**第一优先通道**就是官方直连，此后刷新不再经过任何人

> **已经用 OpenList 公共流程拿到的令牌，无法事后补救**——它只能用 OpenList 的 client_id 刷新。要零第三方就得按上面重新授权一次。

### 用它的服务，合不合适？

> 白嫖人家的东西，让AI分析了一波，感觉还可以，问题不大

合适。把账算清楚，你自己判断就好。

**一是这个接口由 OpenList 主动公开，不是谁逆向来的私有端点。**  
[`OpenList-APIPages`](https://github.com/OpenListTeam/OpenList-APIPages) 在仓库 README 的接口文档里，把 `/renewapi` 的地址、参数（`apps_types` / `refresh_ui` / `server_use`）和返回字段（`access_token` / `refresh_token`）逐项列了出来——**它本来就是写给第三方程序调用的**。项目还提供 Cloudflare / EdgeOne 一键部署按钮、Docker 镜像，以及国内站 `api.oplist.org.cn`：便利版托管让人白用，想完全自持也可以自己搭一份。

**二是用量小到可以忽略，不会给它们带来负担。** 它们的服务器只负责「令牌交换」这一件事：

| 项目                    | 每次消耗                          |
| --------------------- | ----------------------------- |
| 一次令牌刷新                | 1 个 Worker 请求 + 它们服务器 1 次上游请求 |
| 列目录 / 搜索 / 取播放直链 / 下载 | **0**（你的电脑直连阿里云盘，不经过它们）       |

而本插件只在访问令牌失效时才刷新（`access_token` 有效期约 2 小时），于是：

| 使用强度     | 每天发给 OpenList 的请求 |
| -------- | ----------------- |
| 偶尔听一小时   | 1 次               |
| 每天开 4 小时 | 2 次               |
| 挂一整天     | 约 12 次            |

Cloudflare Worker 的免费额度是 10 万次/天，**挂一整天也才用掉万分之一左右**；而且这个服务基本只做转发，不吃 CPU。

唯一需要留意的是：勾选「使用 OpenList 提供的参数」时，用的是**他们注册的公共应用身份**，所有使用者共用——这是共享名额，而不是私人资源。

## 常见问题

**Q：搜索不到东西 / 排行榜是空的？**  
先检查「云盘类型」。很多人的音乐放在**资源库**而不是默认云盘——把这项填成 `all` 就能覆盖全部云盘。

**Q：提示「音乐目录无法访问」？**  
说明「音乐目录」填的路径在该云盘里不存在。检查路径拼写（区分大小写），或先留空用 `root` 从根目录找。

**Q：歌单 / 专辑页是空的？**  
这两页列出的是「音乐目录下的**文件夹**」，并且**只显示含音频的文件夹**。如果你把所有歌都平铺在音乐目录里（没有子文件夹），这两页就是空的——用「排行榜 → 全部歌曲」即可。

**Q：歌词不显示？**  
插件按「同目录同名 `.lrc`」查找。把 `歌曲名.lrc` 和音频放在同一个文件夹里即可。

**Q：会不会很慢 / 撞限流？**  
插件内置了 200 ms 请求节流和限流退避。「全部歌曲」的递归遍历是按时间片跑的，第一页返回后继续下拉会接着爬完剩余目录。

**Q：提示「刷新令牌失败」？**  
说明令牌真的失效了（90 天到期，或已在别处被用掉）。去 [api.oplist.org](https://api.oplist.org) 重新获取一个填进去。

**Q：重启软件后提示令牌失败？**  
理论上 v0.0.8 起桌面版已自动接力保存新令牌，不该再出现。如果仍有，说明本地插件存储被清掉了（比如清过软件数据/缓存），重新获取一个令牌即可。安卓版受限于沙箱暂无这一步，重启后需要重新获取。

## 开发其他网盘的类似插件？用这两段提示词

本插件就是从下面这套需求迭代出来的，**换个网盘名就能复用**。

提示词按用途拆成了两段：

| 段落             | 讲什么                         | 要不要用        |
| -------------- | --------------------------- | ----------- |
| **第一段 · 怎么开发** | 接口依据、功能清单、沙箱限制、测试要求         | 必用          |
| **第二段 · 怎么分享** | 开源协议、LICENSE、仓库放什么、Pages 链接 | 只在打算公开发布时才用 |

分开的原因很简单：第二段里的东西（协议、传仓库、开 Pages）跟插件能不能用**没有任何关系**，只是发布时要办的手续。

> 整套流程依赖 MusicFree 作者维护的官方 Skill 合集 [musicfree-skills](https://github.com/maotoumao/musicfree-skills)：`musicfree-plugin-dev` 负责插件开发（协议、14 种方法签名、沙箱限制、站点分析方法论），`musicfree-themepack-dev` 负责主题包。**不需要你自己安装**——第一段提示词开头就让它装，Agent 会自己安装并使用。

### 复制提示词

在 WorkBuddy / Codex / deepseek-harness 等支持文件读写和联网的 AI 助手里粘贴：

> 请注意务必使用Agent，不要用网页做，肯定是做不出来的，不想花钱可以用腾讯的WorkBuddy，起码现在是能白嫖的，这个项目就是白嫖做出来

> 两段分开粘贴：先发第一段做插件；等做完、能跑了，再发第二段收尾。**不打算分享就直接跳过第二段**，分享起来也不麻烦，只需要准备一个 GitHub/Gitee 账号（Gitee账号需要实名），其余交给 Agent 就行。

#### 第一段：怎么开发

```text
帮我为 MusicFree 开发一个「<网盘名称>」插件，用插件变量（userVariables）存储用户信息。

开工前先安装并加载官方 Skill：npx skills add maotoumao/musicfree-skills（https://github.com/maotoumao/musicfree-skills），严格按其中 musicfree-plugin-dev 的插件协议与行为准则执行。

参考资料一（接口依据）：https://github.com/OpenListTeam/OpenList —— 第一步先去看它 drivers 目录下有没有这个网盘对应的驱动：
- 有驱动：把它读一遍（通常也就一两个文件），摸清真实的接口地址、鉴权方式和参数，直接以它作为接口依据。OpenList 是这类网盘接口最全的一份公开实现，有驱动基本就说明这条路已经被人跑通过。
- 没有驱动：不代表做不了，接着看这个网盘有没有官方开放平台（见硬性要求 2）；两样都没有就停下来告诉我，别硬做。另外注意：没有驱动时成本会明显更高——驱动是别人已经跑通过的现成实现，读一两个文件就能照着写；没有它就只能通读官方文档再一条条实测，文档漏字段、参数名和实际返回对不上都得返工，多花的 token 和时间通常是几倍量级。遇到这种情况你要先把这个代价告诉我、等我确认再往下做，不要闷头试。
如果这个网盘也在 https://api.oplist.org 的支持列表里，可以直接去那里扫码 / 授权拿一个 refresh_token 来做实测，不必从零实现一遍授权流程。（注意：用它的服务意味着令牌的生成、以及后续每次刷新都会经过它的服务器，收尾时要在 README 里如实说明这一点。）

参考资料二（成品范例）：https://github.com/fhvyxyci/musicfree-plugin-aliyundrive —— 这是同类插件已经做完的版本（阿里云盘，带 README）。先通读一遍，看它怎么组织文件、怎么做令牌接力、怎么把「按文件夹的歌单 / 专辑」接进搜索页，再看看它 README 里都有哪些章节（安装、变量、FAQ 是怎么排的），了解这类插件的最终形态和工程化做法。

硬性要求：
1. 严格遵循 musicfree-plugin-dev 里的插件协议与「严格行为准则」（禁止盲猜 URL、禁止靠网络搜索猜 API、禁止批量探测）。所有接口行为都要先用临时脚本对真实接口验证过，再写进插件。
2. 接口来源按这个顺序找，前一步走不通再往下走：① **优先用 OpenList 驱动里那一套**——有驱动就照它来，最省事也最可靠，说明已经有人把它跑通过；② 如果驱动那套必须做私有签名（设备指纹、ECC 签名之类）而沙箱做不了，再看这个网盘有没有「官方开放平台 API」（只要 Bearer token 的那种），有就改用官方——但这条路没有现成实现可参考，得通读官方文档再逐条实测，比我给了你驱动的情况要多花不少 token 和时间，开工前先跟我确认一下；③ 两条都不通——既没有驱动、也没有官方开放平台，或者只能走必须签名而沙箱（只有 axios / crypto-js / big-integer）实现不了的接口——就停下来告诉我这个网盘做不了、建议换一个，不要硬凑；这种情况我会自己另写一套提示词，也就是说本提示词不适用。
3. 插件本体不能依赖任何 npm 包，只能用沙箱内置的。
4. 沙箱里单个函数有执行时间限制，耗时操作（如递归遍历整个网盘）必须做成可跨次续跑的分片任务，不能一次跑到底。
5. 用户变量是只读的，插件没法把刷新后的新令牌写回配置。如果该网盘的 refresh_token 会「刷新即轮换、旧令牌作废」，必须做令牌接力：运行期间存内存；同时用沙箱的 musicfree/storage 把最新令牌落盘（注意给 key 加插件前缀；该模块在移动端可能缺失，取不到要能静默降级，不能因此报错），下次启动优先用落盘的那份。落盘时只存「配置令牌的指纹 + 最新令牌」，用户换了令牌要能自动忽略旧缓存。

需要实现的功能：
- 搜索：单曲（全盘搜音频文件，支持翻页）
- 搜索页的「歌单」和「专辑」标签：把我的音乐目录下的「文件夹」当歌单 / 专辑列出来（两者内容一致，只列含音频的文件夹），点进去显示该文件夹里的歌
- 推荐歌单页：加一个「全部文件夹」标签，不输关键词就能浏览所有文件夹
- 排行榜：两组 ——「全部歌曲（含子目录）」递归汇总所有音频、「目录」按文件夹浏览
- 播放：取直链
- 歌词：自动找同目录同名的 .lrc 文件
- 元数据：优先读网盘文件的内嵌标签（标题 / 歌手 / 专辑 / 封面 / 时长），读不到再从文件名解析（注意别把「01 - 」这种音轨号当成歌手名）
- 自动过滤非音频文件；遇到接口限流要自动退避重试，不要静默吞错

工程要求：
- 写一个离线测试脚本（用 axios 替身模拟接口返回），断言请求结构和字段映射
- 再写一个真实环境体检脚本，我提供令牌后跑通完整链路（刷新令牌 → 排行榜 → 全部歌曲 → 目录 → 搜索 → 播放直链），并校验下载到的文件头是不是真的音频
- 改完必须跑语法检查 + 离线测试，要求 0 失败

插件元信息：
- platform 填「<网盘名称>」
- author 填 <你的名字>
- version 从 0.0.1 开始

先别写代码，先告诉我你打算用哪些接口、怎么鉴权、有没有做不了的环节。

## 原理

| 用途    | 端点                                          |
| ----- | ------------------------------------------- |
| 刷新令牌  | `POST /oauth/access_token`                  |
| 云盘信息  | `POST /adrive/v1.0/user/getDriveInfo`       |
| 目录列表  | `POST /adrive/v1.0/openFile/list`           |
| 文件搜索  | `POST /adrive/v1.0/openFile/search`         |
| 播放直链  | `POST /adrive/v1.0/openFile/getDownloadUrl` |
| 路径查目录 | `POST /adrive/v1.0/openFile/get_by_path`    |

接口路径与参数经以下来源**双重交叉验证**：

- 阿里云盘官方开源 SDK：`alibaba/aliyunpan-ios-sdk` 的 `AliyunpanScope`
- [OpenList](https://github.com/OpenListTeam/OpenList) 的 `drivers/aliyundrive_open` 驱动
- OpenList 令牌服务：`OpenListTeam/OpenList-APIPages`

**为什么不用旧版 API？** 旧版 `api.alipan.com` 每个请求都要做 ECC 设备签名（`X-Signature` + `X-Device-Id`），在插件沙箱里既不现实也容易被风控。开放平台 API 只需标准 `Bearer` token。

**几个实现上的取舍：**

- **一次遍历，两份结果**：递归遍历音乐目录时同时产出「全部歌曲」和「按文件夹分组」两份数据，歌单/专辑页和「全部歌曲」榜单共用同一次爬取，不重复请求。
- **遍历可续跑**：沙箱对单个函数有执行时限，遍历状态存在模块级变量里，每次最多跑 6 秒，翻页时接着爬。
- **只暴露含音频的文件夹**：避免歌单页里混进一堆空目录。

桌面版会把轮换后的最新令牌写入 MusicFree 的本地插件存储（仅本机），同样请勿外传该数据目录。

另外请注意：如果你按[获取刷新令牌](#获取刷新令牌)用 `api.oplist.org` 生成的令牌，**该令牌的产生与后续每次刷新都会经过该第三方服务器**（详见[关于令牌](#关于令牌)）。想要完全私有的链路，只能走自建应用 + 官方直连——前提是你有开发者资格，见[上文](#想完全不经第三方自建应用现在对个人基本走不通)。
