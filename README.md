# MusicFree 插件 —— 阿里云盘

把阿里云盘当作你的私人音乐库，在 [MusicFree](https://github.com/maotoumao/MusicFree) 里搜索、浏览和播放自己云盘上的音乐。

基于**阿里云盘官方开放平台 API**（`openapi.alipan.com`）实现，只需要一个 `refresh_token`，无需抓包、无需设备签名。

- 插件版本：**v0.0.6**
- 作者：fhvyxyci
- 支持平台：MusicFree 桌面版 / 安卓版（插件机制通用）

---

## 功能

| 入口 | 说明 |
|---|---|
| 搜索 → 单曲 | 全盘搜索音频文件（支持翻页） |
| 搜索 → 歌单 | 把「音乐目录」下的**文件夹**当作歌单列出，点进去就是该文件夹里的歌 |
| 搜索 → 专辑 | 与「歌单」内容完全一致（同一批文件夹的另一种呈现） |
| 推荐 → 歌单 | 多一个「全部文件夹」标签，**不用输关键词**就能浏览所有文件夹 |
| 排行榜 | 两组：「**全部歌曲（含子目录）**」递归汇总所有音频；「**目录**」按文件夹逐层浏览 |
| 播放 | 取 4 小时有效的直链播放 |
| 歌词 | 自动查找歌曲**同目录同名的 `.lrc`** 文件（找不到会提示，属正常） |

其他细节：

- 自动读取云盘文件的内嵌标签（标题 / 歌手 / 专辑 / 封面 / 时长），读不到时从 `歌手 - 歌名.flac` 这类文件名解析
- 自动过滤图片、视频、文档等非音频文件
- 支持**多云盘**（默认云盘 / 资源库 / 备份盘），音乐放在资源库里也能正常用
- 接口限流自动退避重试，大曲库递归遍历可跨次续跑，不会卡死

## 安装

### 方式一：网络导入（推荐）

在 MusicFree 中：**侧边栏 → 插件管理 → 从网络安装**，粘贴下面的地址：

```
https://raw.githubusercontent.com/fhvyxyci/musicfree-alipan/main/aliyundrive.js
```

如果 `raw.githubusercontent.com` 访问不通（国内网络常见），改用 jsDelivr 镜像：

```
https://cdn.jsdelivr.net/gh/fhvyxyci/musicfree-alipan@main/aliyundrive.js
```

### 方式二：本地导入

从仓库下载 `aliyundrive.js`，在 **插件管理 → 从本地文件安装** 中选中它。

> 插件本体**不依赖任何 npm 包**，只使用 MusicFree 沙箱内置的 `axios`，可直接安装。

安装后在插件列表里**启用**它，然后点进插件设置填写变量（见下一节）。

## 变量怎么填

插件设置里共有 6 项，**只有第 1 项是必填的**：

| # | 变量 | 必填 | 填什么 |
|---|---|---|---|
| 1 | **刷新令牌 (refresh_token)** | ✅ | 见下方「如何获取刷新令牌」 |
| 2 | **音乐目录** | 选填 | 留空或填 `root` = 从云盘根目录开始；也可填目录路径（如 `/music`）或目录 ID；多个目录用**英文逗号**分隔 |
| 3 | **云盘类型** | 选填 | `all`（全部云盘，**默认，推荐**）/ `default`（仅默认云盘）/ `resource`（仅资源库）/ `backup`（仅备份盘） |
| 4 | 客户端ID (ClientID/AppID) | 选填 | 自建应用的 AppId。填了之后令牌**直接向官方接口刷新**，不经过任何第三方 |
| 5 | 应用密钥 (AppSecret) | 选填 | 与第 4 项配套，**两项都填**才会走官方直连 |
| 6 | 令牌刷新服务地址 | 选填 | 仅在没填第 4、5 项时生效，默认 `https://api.oplist.org/alicloud/renewapi`，不用改 |

### 最小可用配置

```
刷新令牌   : <粘贴你获取到的 refresh_token>
音乐目录   : /music        ← 换成你自己的音乐文件夹路径
云盘类型   : all
（其余留空）
```

> **不知道音乐目录在哪？** 把「音乐目录」留空（或填 `root`），先装好插件去**排行榜 → 目录**里看看你的云盘结构，找到音乐文件夹后，再把路径填回去即可。

### 如何获取刷新令牌

1. 浏览器打开 **<https://api.oplist.org>**
2. 驱动下拉选 **「阿里云盘 应用登录」**
   （⚠️ 不要选「阿里云盘 直接登录」，那个流程的服务端刷新接口有 bug，上游会拒）
3. **勾选**「使用 OpenList 提供的参数」，ClientID 与 AppSecret **都留空**
4. 点「获取 Token」→ **用阿里云盘 App 扫码登录**
5. 复制返回的 **Refresh Token**，粘贴到插件设置的第 1 项

### ⚠️ 关于令牌失效

官方文档写明 refresh_token 是「单次有效」的：刷新后会签发新令牌，旧令牌作废。

但 MusicFree 的插件变量是**只读**的——插件没法把新令牌写回配置。本插件的处理方式是：

- 刷新拿到的新令牌与 `access_token` 一起存在**内存**里接力，同一次运行期间只刷新一次，之后长期可用；
- 因此**日常使用不受影响**；只有重启软件后，才会再用一次你填的那个原始令牌。

如果哪天提示「刷新令牌失败」，说明那个令牌已经被别处用掉或过期了，**重新获取一个填进去即可**。

> 如果你有自建应用（ClientID + AppSecret），填上第 4、5 项走官方直连，令牌完全不经过第三方服务，更安全。

## 常见问题

**Q：搜索不到东西 / 排行榜是空的？**
先检查「云盘类型」。很多人的音乐放在**资源库**而不是默认云盘——把这项填成 `all` 就能覆盖全部云盘。

**Q：提示「音乐目录无法访问」？**
说明「音乐目录」填的路径在该云盘里不存在。检查路径拼写（区分大小写），或先留空用 `root` 从根目录找。

**Q：歌单 / 专辑页是空的？**
这两页列出的是「音乐目录下的**文件夹**」，并且**只显示含音频的文件夹**。如果你把所有歌都平铺在音乐目录里（没有子文件夹），这两页就是空的——用「排行榜 → 全部歌曲」即可。

**Q：歌词不显示？**
插件按「同目录同名 `.lrc`」查找。把 `歌曲名.lrc` 和音频放在同一个文件夹里即可。

**Q：会不会很慢 / 撞限流？**
插件内置了 200 ms 请求节流和限流退避。「全部歌曲」的递归遍历是按时间片跑的，第一页返回后继续下拉会接着爬完剩余目录。

## 开发其他网盘的类似插件？用这段提示词

本插件就是从下面这段需求迭代出来的，**换个网盘名就能复用**。直接在 WorkBuddy / Claude 等支持文件读写和联网的 AI 助手里粘贴：

````text
帮我为 MusicFree 开发一个「<网盘名称>」插件，用插件变量（userVariables）存储用户信息。

参考资料：先去 https://github.com/OpenListTeam/OpenList 的 drivers 目录下找到
这个网盘对应的驱动，读它的源码，摸清真实的接口地址、鉴权方式和参数，
作为接口依据。

硬性要求：
1. 先加载 musicfree-plugin-dev 技能，严格按 MusicFree 插件协议写。
2. 优先使用该网盘的「官方开放平台 API」（只需要 Bearer token 的那种）。
   如果某个接口必须做私有签名（如设备指纹、ECC 签名），先评估
   MusicFree 沙箱能不能做（沙箱只有 axios / crypto-js / big-integer），
   做不了就换官方开放平台，别硬凑。
3. 插件本体不能依赖任何 npm 包，只能用沙箱内置的。
4. 沙箱里单个函数有执行时间限制，耗时操作（如递归遍历整个网盘）
   必须做成可跨次续跑的分片任务，不能一次跑到底。

需要实现的功能：
- 搜索：单曲（全盘搜音频文件，支持翻页）
- 搜索页的「歌单」和「专辑」标签：把我的音乐目录下的「文件夹」当歌单/专辑
  列出来（两者内容一致，只列含音频的文件夹），点进去显示该文件夹里的歌
- 推荐歌单页：加一个「全部文件夹」标签，不输关键词就能浏览所有文件夹
- 排行榜：两组 ——「全部歌曲（含子目录）」递归汇总所有音频、「目录」按文件夹浏览
- 播放：取直链
- 歌词：自动找同目录同名的 .lrc 文件
- 元数据：优先读网盘文件的内嵌标签（标题/歌手/专辑/封面/时长），
  读不到再从文件名解析（注意别把「01 - 」这种音轨号当成歌手名）
- 自动过滤非音频文件；遇到接口限流要自动退避重试，不要静默吞错

工程要求：
- 写一个离线测试脚本（用 axios 替身模拟接口返回），断言请求结构和字段映射
- 再写一个真实环境体检脚本，我提供令牌后跑通完整链路（刷新令牌 → 排行榜
  → 全部歌曲 → 目录 → 搜索 → 播放直链），并校验下载到的文件头是不是真的音频
- 改完必须跑语法检查 + 离线测试，要求 0 失败

插件元信息：
- platform 填「<网盘名称>」
- author 填 <你的名字>
- version 从 0.0.1 开始

先别写代码，先告诉我你打算用哪些接口、怎么鉴权、有没有做不了的环节。
````

**几点使用建议：**

- **第一轮先要方案，别直接要代码**——最后那句「先告诉我你打算用哪些接口」很关键，能提前发现鉴权死路（很多网盘的私有 API 需要复杂签名，沙箱做不了）。
- **准备好一个真实令牌**，方便对方做端到端验证。插件这类东西，不跑真实链路是验证不了的。
- **接口字段名要靠实测**：不同网盘返回的字段命名风格不统一（阿里云盘就是外层 `snake_case`、内层 `camelCase`），一定要用真实返回去校对，别只看文档。
- **要求对方先写临时探测脚本**验证接口行为，确认后再写进插件，用完删掉——直接猜接口很容易白写。

适合套用的网盘：百度网盘、115、天翼云盘、123 云盘、夸克网盘、OneDrive、Google Drive、WebDAV / 群晖等。

## 原理

| 用途 | 端点 |
|---|---|
| 刷新令牌 | `POST /oauth/access_token` |
| 云盘信息 | `POST /adrive/v1.0/user/getDriveInfo` |
| 目录列表 | `POST /adrive/v1.0/openFile/list` |
| 文件搜索 | `POST /adrive/v1.0/openFile/search` |
| 播放直链 | `POST /adrive/v1.0/openFile/getDownloadUrl` |
| 路径查目录 | `POST /adrive/v1.0/openFile/get_by_path` |

接口路径与参数经以下来源**双重交叉验证**：

- 阿里云盘官方开源 SDK：`alibaba/aliyunpan-ios-sdk` 的 `AliyunpanScope`
- [OpenList](https://github.com/OpenListTeam/OpenList) 的 `drivers/aliyundrive_open` 驱动
- OpenList 令牌服务：`OpenListTeam/OpenList-APIPages`

**为什么不用旧版 API？** 旧版 `api.alipan.com` 每个请求都要做 ECC 设备签名（`X-Signature` + `X-Device-Id`），在插件沙箱里既不现实也容易被风控。开放平台 API 只需标准 `Bearer` token。
